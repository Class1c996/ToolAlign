# Public release checklist

## Included in the repository

- Deterministic environment, task generation, SFT/interactive-GRPO source, tests and CI.
- Explicit suite manifest: `data/suites.json`.
- Small public task examples generated by `scripts/export_public_examples.py`.
- Canonical experiment summary: `reports/generalization_summary.json`.
- Configurations and exact commands; no model weights, adapters, logs, or full rollout traces.

## Excluded before publishing

- `models/`, `checkpoints/`, `.venv/`, downloads, logs and generated rollout JSONL.
- Training-only corpora and large processed state-counterfactual data.
- API keys, credentials, local editor state and database snapshots.

## Before creating a remote repository

1. Run `python -m pytest -q`, `python scripts/reproduce.py --suite public_smoke`, and `python scripts/check_public_release.py`.
2. Review `git status --ignored` and confirm no weights, adapters, private paths or large artifacts are staged.
3. Review the current README and `docs/06-最终实验结论与复现.md`; metrics must match `reports/generalization_summary.json`.
4. The configured remote is `Class1c996/ToolAlign`; push only after checking the staged file list and repository visibility.

## Known scope limits

- Results are from a single training seed on one local Qwen3-1.7B setup.
- State/value and wording holdouts each contain 20 tasks; they are useful but not confidence intervals.
- BFCL and xLAM are discussed as external benchmarks/data directions, not executed headline results.
- The interactive GRPO implementation was evaluated as a small ablation and was not selected because it did not improve success and slightly reduced broad JSON legality.
