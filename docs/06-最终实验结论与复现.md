# ToolAlign 最终实验结论与复现

项目性质：2026 年 7 月、约两周完成的个人独立项目。主实验在 NVIDIA RTX
5080 16GB 上使用 Qwen3-1.7B 与 QLoRA；训练与评测采用单一随机种子。

## 结论

当前选择的模型是 `checkpoints/sft_multitask_state_v5`，而不是 GRPO
checkpoint。它通过了三个互相独立的可执行评测：广泛任务、措辞 holdout
和状态/数值 holdout。所有成功率均要求完整的工具调用轨迹、成功的工具执行
以及最终回答，而不是只看某一步是否选中了工具。

| 评测集 | Base | 最佳多任务 SFT | 小规模交互式 GRPO |
| --- | ---: | ---: | ---: |
| challenge_v1（120）端到端成功率 | 55.83% | **74.17%** | 74.17% |
| challenge_v1 工具成功率 | 91.67% | **100.00%** | 100.00% |
| state/value holdout（20）端到端成功率 | 45.00% | **60.00%** | 60.00% |
| critical wording holdout（20）端到端成功率 | 未记录 | **70.00%** | 未评测 |

最佳 SFT 在前两套主评测中的假完成率均为 0；state/value holdout 的格式、
工具与参数成功率均为 100%。广泛 challenge 的格式合法率为 99.17%，措辞
holdout 为 95.00%，因此格式稳健性仍是最重要的后续改进方向。

## 为什么 GRPO 不是最终模型

本项目实现的是交互式 rollout：模型生成 JSON 动作，环境执行工具并把结果
写回上下文，然后模型继续生成。小规模 GRPO 在状态 holdout 和广泛 challenge
上没有降低端到端成功率，但也没有提高成功率，并把广泛 challenge 的 JSON
合法率从 99.17% 降至 98.33%。因此它是有价值的负向消融，而不是被挑选出来
的“更好模型”。这避免了把训练完成或奖励上升错误包装为能力提升。

## 面试展示重点

1. 先建立能执行工具、保存状态、记录完整轨迹的确定性环境。
2. 用 state/value holdout 识别“固定常量刷分”；早期 Critical SFT 的主集高分在
   该 holdout 上甚至低于 Base。
3. 修复 SFT 的状态回放，并使用与 holdout 隔离的随机化状态和原始多任务数据
   混训，得到真实提升。
4. 对交互式 GRPO 做完整消融，保留负结果和格式回退，而不是选择性报告。

逐条模型轨迹保留在本地 `reports/` 且不随公开仓库发布；公开仓库只保留小型
汇总指标。模型权重与 checkpoint 同样不发布。

## 结果边界

- `challenge_v1` 为 120 条自建可执行任务；两个 holdout 各 20 条，不构成大规模
  外部基准或置信区间。
- BFCL non-live 与 xLAM 是代码中的适配/数据方向，不是已经完成的主结果。
- 当前结果只有单 seed；多 seed、扩大 holdout 与正式 BFCL 是后续工作。
- GRPO 只作为小规模真实交互消融，未提升成功率，因此不选择其 checkpoint。
